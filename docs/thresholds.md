# Пороги категорий

По умолчанию `THR_DANGEROUS=0.75`, остальные категории 0.5.

## Почему `dangerous` 0.75

При 0.5 precision по `dangerous` на выборке из `val.jsonl` была 0.69. 38% ложных срабатываний приходились на
записи с одним лейблом `spam`: модель плохо разделяет эти два класса на уровне признаков. Квантование и код сервиса
тут ни при чём.

При 0.75 precision 0.90, а recall тот же, что при 0.70: между 0.70 и 0.75 в вероятностях лежит кластер безопасного
контента.

Порог лечит симптом. Если доля спама в проде вырастет, ложных `dangerous` снова станет больше. Исправлять это нужно
дообучением на данных, где spam и dangerous явно разделены.
